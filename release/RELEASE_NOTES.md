# Release notes for the next build

Copy this file to `release/RELEASE_NOTES.md` when a new build is cut, and fill it in. The body of
a published release is this text, so write it for someone deciding whether to install the build.

A good release note answers three questions:

1. **What changed** — the behaviour a user can see, grouped by area, in plain words.
2. **How to install it** — the file name, the checksum, the application id, and what it does to
   an existing installation.
3. **What was not tested** — the checks that were skipped, and the limits that still hold.

Keep the development builds' habit of stating the limits plainly. The verification report that
travels with the release says what was checked; the release note says what a reader should still
be careful about.

The current release's notes are published with it, on the
[releases page](https://github.com/Abhiroop1122/runout/releases).
