# Android flow checks with Argent

Runout uses pinned Argent **0.29.0** as development tooling. Install outside the app with `npm install --prefix /path/to/argent @swmansion/argent@0.29.0`, then use `/path/to/argent/node_modules/.bin/argent`. Add Android SDK `platform-tools` and `emulator` to `PATH`. Project telemetry is disabled in `config.json`.

Run `argent run list-devices`, then `argent flow run .argent/flows/offline-navigation.yaml --device <serial>`. The offline flow works on a new installation or an onboarded home screen. `offline-song-search` additionally needs the checked-in Night Drive fixtures copied to a device music folder and selected through the Android picker. Other flows declare their starting states; use `argent run describe` to inspect the current screen before running a fragment.

Runout's home is the listening room. Its footer is a row of four icon tabs that always fits (`nav:DIG`, `nav:DROPS`, `nav:FRIENDS`, `nav:SETTINGS`). Each tab opens a glass sheet that closes with `action:Close`. A fresh install starts with a short intro (`onboarding-intro`, tap to skip), then a full-screen sign-in (`field:Soulseek ID`, `field:Password`, `submit-soulseek`, and `setup-offline` to skip). Later steps move on by themselves after a choice; there are no Continue buttons. Downloads open from `open-downloads` (the `↓ N` dot by the record count), and the account from `open-account`. Search never plays anything: "Put on the platter" cues the song on the deck with the needle up, and only the deck's START/STOP plays it.

For an explicit public-network check, put `ARGENT_SECRET_SLSK_USERNAME` and `ARGENT_SECRET_SLSK_PASSWORD` in `.argent/secrets.env` with mode 0600. This file is ignored. Flows use secret placeholders, not actual credentials. Remove the file and sign out of the test device after testing. Run one client per account; do not let separate emulator sessions displace each other.

The sign-in flow deliberately taps a field, waits for the keyboard/layout to settle, then types through the keyboard tool. This avoids input loss with immediate focus/type sequences on native Compose fields. A successful login must be proved by the next screen; a reported tap/type alone is insufficient evidence.

`live-discovery` searches once and never downloads or sends messages. Public availability is variable. `picker-recovery` opens and cancels the Android folder picker and requires the account to be online again on return, without re-entering credentials. Android may briefly interrupt a cached app's sockets while its picker is open. Do not include public-account screenshots, private messages, generated tool-server state or account files in a commit.

The instrumentation live probe is separate and skipped by default. See `docs/BUILDING.md` for provisioning its private account file and running it intentionally. Ordinary CI uses local fixtures only.

On development emulators, gRPC gestures can be treated as stylus input and trigger Android's handwriting toolbar. That can defer typed text and make Back leave the screen. For an emulator used for these keyboard flows, disable handwriting with `adb -s <emulator> shell settings put secure stylus_handwriting_enabled 0`, then refocus the field and verify its contents. This is a test-device setting, not an app requirement or a change to a user's phone. Wait for the keyboard/layout to settle before typing; never retry secret text blindly into a field that may already contain it.

For network recovery, use only a disposable test emulator. With Runout connected on its main screen, disable both Wi-Fi and mobile data using the emulator controls, run `network-offline`, restore both, then run `network-online`. Always restore the network even when an assertion fails. Repeat twice. The offline flow proves the same account view remains available for more than six seconds, and the online flow requires reconnection without visiting sign-in. Do not run a separate client or instrumentation concurrently.
